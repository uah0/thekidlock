# Задача

Добавить в существующий проект второй способ открытия замка.

Первый способ должен продолжать работать без изменений.

---

## Уже реализовано

Проект уже содержит:

- OTA
- Wi-Fi
- Web-интерфейс
- BLE Scanner
- поиск пяти BLE-маяков по имени
- алгоритм открытия замка
- таймер А
- таймер Б
- управление буззером
- управление GPIO замка

Весь существующий функционал обязан сохраниться.

---

# Новый способ открытия

Добавить возможность открытия телефона.

Схема работы:

Телефон

↓

BLE Pairing

↓

BLE Bonding

↓

Encrypted BLE Connection

↓

Команда OPEN

↓

Существующий автомат открытия

Никакой новой логики открытия создавать нельзя.

Телефон должен использовать тот же автомат открытия, что и BLE-маяки.

---

# Этап 0

Выполнить аудит.

Найти:

- BLE Stack
- BLE Scanner
- алгоритм открытия
- таймер А
- таймер Б
- Web-интерфейс
- OTA
- хранение настроек

Создать файл:

AUDIT.md

После аудита перечислить:

- какие файлы будут изменяться;
- какие новые файлы появятся;
- какие риски существуют.

До окончания аудита код не менять.

---

# Этап 1

Создать единый интерфейс открытия.

Например:

lock_request_open()

Существующие BLE-маяки должны использовать именно этот интерфейс.

Работа проекта измениться не должна.

---

# Этап 2

Добавить BLE GATT Server.

Создать собственный Service UUID.

Добавить характеристики:

LOCK_INFO

LOCK_COMMAND

LOCK_STATUS

Добавить Advertising.

На данном этапе команда OPEN должна только выводиться в лог.

Замок открываться ещё не должен.

---

# Этап 3

Добавить стандартный BLE Pairing.

Использовать:

LE Secure Connections

Bonding

Не использовать:

- собственные ключи;
- HMAC;
- счётчики;
- собственную криптографию.

---

# Этап 4

Добавить режим регистрации телефона.

Через Web-интерфейс должна появиться кнопка

Разрешить регистрацию телефона

После её нажатия:

в течение 60 секунд разрешается Pairing нового телефона.

После окончания времени Pairing автоматически запрещается.

Уже зарегистрированные телефоны продолжают работать.

---

# Этап 5

Команда OPEN.

Замок открывается только если:

- соединение зашифровано;
- устройство Bonded;
- Pairing завершён;
- RSSI выше установленного порога.

После проверки необходимо вызвать существующий автомат открытия.

Запрещается управлять GPIO непосредственно из BLE callback.

---

# Этап 6

Добавить отдельный RSSI порог для телефона.

Начальное значение:

-68 dBm

Порог должен настраиваться через Web-интерфейс.

---

# Этап 7

Добавить страницу BLE.

На странице должны отображаться:

- разрешён ли Pairing;
- оставшееся время регистрации;
- список Bonded устройств;
- удалить Bond;
- порог RSSI.

---

# Совместимость

После завершения проекта одновременно должны работать:

1. Пять существующих BLE-маяков.

2. Телефон.

Они должны использовать один и тот же алгоритм открытия.

---

# Что НЕ делать

Не писать Android-приложение.

Не использовать внешнюю память.

Не реализовывать собственный криптографический протокол.

Не удалять существующий функционал.

---

# Критерии завершения

Проект считается выполненным только если:

- полностью собирается;
- старые BLE-маяки работают;
- Pairing выполняется;
- Bonding сохраняется;
- телефон может открыть замок через защищённое соединение;
- после перезагрузки ESP32 Bonding сохраняется;
- проект успешно проходит тестирование.
