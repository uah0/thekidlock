# BLE Lock ESP32-S3

## Переносимый AI Agent

Стандартный Agent API выделен в `components/ai_agent/`; конфигурация, команды и
диагностика замка подключены через `main/lock_ai_adapter.c`. Сервер остаётся общим
с Web UI. Инструкция подключения к другому ESP-IDF проекту, пример реле,
контракты callbacks и ограничения безопасности: [AI_AGENT_COMPONENT.md](AI_AGENT_COMPONENT.md).

```powershell
.\device-agent.ps1 capabilities -Device 192.168.1.41
.\device-agent.ps1 command open
.\device-agent.ps1 flash firmware.bin
```

Клиент поддерживает любое устройство с Agent API v1 независимо от модели и
формата firmware version. После OTA проверяет возврат того же устройства и
перезапуск, выводит предыдущую и текущую версии. Прежние команды и Web URI
сохранены. API предназначен для доверенной локальной сети, без прямого доступа
из Internet до реализации authentication/authorization.

## Локальная диагностика устройства из Codex

После прошивки ESP32 должна быть подключена к той же локальной сети, что и
компьютер. Проектный клиент сохраняет последний успешный адрес в игнорируемом
каталоге `.device-agent`.

```powershell
# Найти устройство среди адресов, уже известных ARP-кэшу Windows
.\device-agent.ps1 -Action discover

# Если автоматическое обнаружение не сработало, указать адрес один раз
.\device-agent.ps1 -Action snapshot -Device 192.168.1.41

# Полный снимок, журнал и непрерывное наблюдение
.\device-agent.ps1 -Action snapshot
.\device-agent.ps1 -Action events
.\device-agent.ps1 -Action watch -IntervalMs 500

# Полный прикладной ESP-IDF журнал и его непрерывное чтение
.\device-agent.ps1 -Action log
.\device-agent.ps1 -Action monitor -IntervalMs 250

# Временно включить/выключить подробные периодические ULP-строки
.\device-agent.ps1 -Action diagnostics-on
.\device-agent.ps1 -Action diagnostics-off

# Команды автомата и прямые тестовые команды ULP
.\device-agent.ps1 -Action open
.\device-agent.ps1 -Action close
.\device-agent.ps1 -Action auto
.\device-agent.ps1 -Action always-open
.\device-agent.ps1 -Action ulp-lock
.\device-agent.ps1 -Action ulp-unlock

# Проверка бипера: 1..6 коротких сигналов или 7 = тире и три точки
.\device-agent.ps1 -Action buzzer -BuzzerPattern 1
.\device-agent.ps1 -Action buzzer -BuzzerPattern 7

# Перезапуск и загрузка текущего build по Wi-Fi, без COM-порта
.\device-agent.ps1 -Action restart
.\device-agent.ps1 -Action flash -Device 192.168.1.41
```

Клиент не сканирует всю подсеть. В текущем тестовом режиме HTTP Agent API v1 не
требует аутентификации и предоставляет все команды автомата, прямые команды ULP,
тест бипера, перезапуск и OTA. GPIO9 не записывается главным ядром напрямую:
силовым выходом единолично управляет ULP, что исключает конфликт владельцев.
Интерфейс предназначен только для доверенной локальной сети.

Прошивка BLE-замка для ESP32-S3 с Web UI, OTA, RGB-индикацией и бипером на
GPIO8. В автоматическом режиме Android-приложение публикует connectable BLE
advertising; ESP32 сканирует его, после проверки маркера и RSSI устанавливает
одно исходящее соединение, проверяет сохранённый bond и зашифрованное GATT-чтение,
затем открывает замок или продлевает таймер А и отключается. ESP32 работает
только как Observer/Central: собственного BLE advertising и GATT-сервера у замка нет.
Регистрация и обмен настройками происходят через защищённый GATT-сервер телефона.

## Безопасность и регистрация

- Используется одно исходящее BLE-соединение ESP с телефоном. До 20 bonds хранятся
  в NVS; входящих Peripheral-слотов и списка допуска для рекламы ESP нет.
- Новый телефон можно привязать в окне регистрации, открываемом кнопкой BOOT
  или через Web UI; штатное окно длится 60 секунд.
- Используется стандартное BLE bonding и шифрование с настройкой Secure Connections
  Just Works (`NO_IO`, без MITM); SC-only не включён.
- Bonds сохраняются в NVS и удаляются из Web UI по одному или все сразу.
- Автоматическое открытие требует сохранённого bond, зашифрованного GATT proof
  телефона и достаточного RSSI. Алгоритм открытия и таймеры А/Б сохранены.
- Настройки Wi-Fi и передача IPv4 доступны через защищённые характеристики телефона
  после проверки владельца. Web UI доступен в сети hotspot телефона; OTA и журналы
  Agent API доступны также в домашней сети.
- Мощность передатчика ESP фиксирована в прошивке: +9 dBm. Ползунок Android
  регулирует мощность BLE-маяка телефона.

## Замок

Замок — fail-safe электромагнит, MOSFET которого управляется GPIO9. Для
запирания питание подаётся, а команда открытия снимает питание.
Физический GPIO закреплён ULP-разводкой и не меняется в runtime.

LED, BLE и HTTP показывают подтверждённое состояние ULP, а не принятую команду.
`FAULT` и `CLOSE_REJECTED` имеют фиолетовую индикацию; `STARTING` означает отсутствие
актуального подтверждения. HTTP отдельно возвращает `requested_open`, `state`,
`locked`, `fault_flags`; `open` равен null при неизвестном состоянии или fault.
После ADC/SENSE/COIL_OPEN выполняются максимум три повтора с паузой не менее 5 s;
COIL_SHORT/STATE_INVALID автоматически не сбрасываются. Проверка контакта сохраняется.
Калибровка снимает питание катушки и автоматически завершается через 120 s
таймером прошивки (проверка каждые 100 ms), даже без открытого браузера.
После завершения действует последняя команда. Уже выполняющееся сохранение NVS
может задержать обработку таймаута до освобождения mutex.

После `OPEN` таймер А продлевается очередным успешным защищённым чтением телефона
при достаточном RSSI. Если подтверждений нет, замок закрывается по таймеру А.
При переходе на новую схему на действующем замке выставлено 5000 ms: 1000 ms
оказалось меньше времени между повторными защищёнными соединениями.

## Web UI

Интерфейс показывает BLE-соединение, encryption, bonding и RSSI; позволяет
настроить RSSI и таймер А, открыть окно
регистрации, управлять bonds, выполнить тест открытия и загрузить OTA.

## Сборка

Проект рассчитан на ESP-IDF 5.4.4 (EIM):

```powershell
pwsh.exe -NoProfile -ExecutionPolicy Bypass -File .\build-esp32.ps1
pwsh.exe -NoProfile -ExecutionPolicy Bypass -File .\build-esp32.ps1 -Action flash-monitor
```

Перед подключением силовой цепи проверьте мультиметром выбранную полярность:
GPIO ESP32 не должен питать электромагнит напрямую, необходим подходящий ключ и
защита от выброса самоиндукции.

## Android-маяк

Приложение `android_lock_beacon` в режиме AUTO запускает foreground service,
connectable legacy advertising (`ADVERTISE_MODE_LOW_LATENCY`,
`ADVERTISE_TX_POWER_HIGH`) и GATT server. Экспериментальный manufacturer ID
`0xF0E1`; данные: `LOCK` (4 байта), версия `01` (1), device ID (4), session ID
(4). Эти открытые данные нужны только для поиска; они не являются ключом.
Защищённая характеристика `6f4f0011-9a7b-4c21-8d32-5e6f708192a3` доступна
только по зашифрованному соединению. Замок также проверяет сохранённый bond.
Для работы маяка включите автоматический режим в приложении.

## Диагностика выбора Wi-Fi

В прошивке 10.0.172 добавлены сообщения с маркером `WiFiDiag`:

```powershell
.\device-agent.ps1 log
.\device-agent.ps1 monitor
.\device-agent.ps1 events
```

После воспроизведения перехода на телефон сохраните `log` до перезапуска ESP32:
журнал хранится в кольце RAM 32 KiB и старые строки вытесняются. Счётчик attempts
считает попытки с начала загрузки. Сообщения содержат saved/phone_runtime SSID,
результат запуска подключения, association, DHCP/IP, reason code/name и RSSI,
таймаут ожидания IP и решение `phone accepted/rejected`.
Причины допуска телефона: `auto_connect_disabled`, `saved_credentials_incomplete`,
`status_ERROR_WIFI`. `current_ap` показывает фактическую ассоциацию при решении;
`ap_info` — результат её чтения. Последний disconnect является историческим
событием и может относиться к предыдущему соединению, что отмечено в сообщении.
В версии 10.0.172 строка `IP recovered but status remains ERROR_WIFI` выявила
устаревший статус после восстановления сети. Начиная с 10.0.174 после получения
IP обновляется `WEB_READY;IP` работающего Web UI; действующее подключение к
сохранённой сети при включённом auto_connect дополнительно защищено от замены
телефоном независимо от старого `ERROR_WIFI`. Лог отказа содержит
`saved_connected=1` и `current_ap`; восстановление отмечено `Web status refreshed`.
Активное сканирование доступности сохранённой сети не добавлено; логи не доказывают
наличие AP в эфире. Пароли и полные BLE payload в новые сообщения не выводятся.
При выключенном auto_connect или неполных saved credentials прежний допуск
телефона сохраняется. Автоматический переход с уже активного phone hotspot
обратно к saved сети этим исправлением не добавляется.

## Отказоустойчивость и диагностика (25.09.2026)

После регистрации телефона перезагрузка не выполняется. ULP и lock control
инициализируются перед Wi-Fi/BLE; ошибки второстепенных модулей диагностируются
без esp_restart/abort. Ошибки NVS не приводят к автоматическому стиранию bonds,
владельца и калибровки. Если NVS недоступен, BLE provisioning не запускается.

**Ограничение:** явный restart/OTA, аппаратный reset и потеря питания не имеют
гарантии непрерывного запирания. Текущий старт ULP делает halt/reset и gate=0.
Принудительно удерживать GPIO9 по старому программному статусу опасно: это может
сохранить питание катушки при отказе и обойти защиту ULP. Для устранения импульса
нужен отдельный проверенный механизм передачи управления ULP/GPIO и измерение
на реальном GPIO9 при каждом типе reset; для потери питания — аппаратное решение.
RTC GPIO hold фиксирует уровень/конфигурацию вывода, но сам по себе не заменяет
проверку всего пути загрузки и защиты катушки:
https://docs.espressif.com/projects/esp-idf/en/v5.4.4/esp32s3/api-reference/peripherals/gpio.html

DELETE /api/ble/bonds требует address=MAC или явное all=1. Пустой/повреждённый
query не удаляет все телефоны. UI использует all=1 с подтверждением.
RSSI для допуска/удержания — медиана трёх измерений (100 ms), после разрыва или
ошибки измерения окно сбрасывается; это не защита от relay. Таймеры А/Б сохранены.

accepted:true в Agent API означает приём запроса обработчиком/очередью, а не
доказательство физического закрытия. Команды ulp_lock/ulp_unlock дополнительно
ждут acknowledgement ULP (до 750 ms); при timeout команда не отменяется и может
быть исполнена позже. Фактический результат проверяется через status/ulp.

Status содержит stack_lock_bytes, stack_ble_bytes, stack_http_bytes — минимальный
наблюдённый свободный стек (байты ESP-IDF), а также nvs_free_entries (-1 при ошибке).
NVS partition остаётся 24 KiB: её расширение требует отдельной миграции таблицы
разделов и данных, обычная OTA приложения этого не делает. Wi-Fi driver использует
WIFI_STORAGE_RAM; пользовательские настройки сохраняются существующим кодом NVS.
Monitor выдаёт до 1024 байт за запрос; cursor нужно продолжать до чтения всего журнала.


## Сборочная гигиена и калибровка

Без сохранённой корректной калибровки замок не может закрыться. BLE/HTTP сообщают
`CALIBRATION_REQUIRED`, LED — пурпурный, Web UI показывает пояснение и ссылку на
калибровку. В status есть `calibration_required`, в /api/ulp — `calibration_valid`.
Во время мастера статус `CALIBRATING`; после успешного сохранения предупреждение
снимается. Отсутствие калибровки не заменяется фиктивными значениями.

Main CPU сейчас использует отладочную оптимизацию `-Og` (явно в sdkconfig.defaults),
ULP — `-Os`. Это разные сборки. Для выпуска с другой оптимизацией нужны отдельные
проверки таймингов, стека и GPIO/ADC; автоматически менять флаги при чистке нельзя.
Текущий профиль ULP 8: период 40 ms, off-guard 10 ms, импульс 2 ms; контроль после
закрытия использует отдельный guard 100 ms. Старые профили оставлены для стенда.
Название experiment_config.h историческое, аппаратная квалификация профиля не
объявляется завершённой только переименованием макроса.

Архив текущих исходников: `python tools/package-project.py`. Скрипт учитывает
незакоммиченные файлы, исключает sdkconfig/sdkconfig.old, кеши/результаты сборки,
локальные настройки и ключи; включает sdkconfig.defaults и sdkconfig.defaults.esp32s3.
Локальные sdkconfig остаются для сборки. .gitattributes задаёт LF для текста,
CRLF для .bat/.cmd; смешанные окончания строк исправлены без переформатирования кода.
