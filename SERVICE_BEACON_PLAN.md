# Переход на один служебный BLE-маяк

Дата: 04.10.2026. Резервный коммит до работ: 1f21136.

1. Исходная проверка: Android build 198 PASS; ESP 10.0.325 PASS, OTA 10.0.324 → 10.0.325 PASS.
2. ESP32: добавить единый служебный маркер 0x83 и защищённые характеристики запроса (001b) и подтверждения команды (001c). Сначала сохранить приём старых 0x81/0x82 для установки прошивки перед APK. Собрать и сразу прошить, проверить firmware_version.
3. Android: публиковать только AUTO 0x01 либо служебный 0x83. Через GATT передавать список операций: Wi-Fi, запрос Web IP, постоянное открытие. Сохранить существующие характеристики Wi-Fi/IP и жизненный цикл одного рекламного набора.
4. Кнопка постоянного открытия отправляет явное SET_HOLD_OPEN=true/false, не toggle: повтор запроса после потери ответа не инвертирует состояние. Только зашифрованный bonded owner может выполнить команду. ESP вызывает существующий lock_request_set_hold_open; подтверждение отправляет после проверки результата автоматом, а не сразу после помещения в очередь.
5. Android показывает ожидание, сопоставляет подтверждение с ID запроса, завершает по ответу/таймауту (30 с), не сохраняет незавершённые команды для повторного исполнения после перезапуска. AUTO и другие служебные операции сохраняют свои настройки.
6. Проверки: ошибочные/устаревшие ответы, совместный запрос Wi-Fi/IP, AUTO OFF, постоянное открытие ON/OFF, завершение/таймаут рекламы, повтор команды, Bluetooth lifecycle. После этапа Android собрать проектным скриптом, запустить относящиеся unit-тесты, установить APK с сохранением ориентации. Проверить на физических ESP/телефоне.
7. После подтверждённой установки нового APK убрать приём старых служебных маркеров из ESP. Собрать/OTA/проверить возврат. Обновить README, AUDIT.md, CHANGELOG.md, TEST_REPORT.md.

## Контракт GATT v1

Реклама: manufacturer marker LOCK, mode=0x83, существующие device_id/session_id. Команды и credentials не передаются в рекламе.
Запрос 001b (encrypted read): 7 байт: version=1, flags (Wi-Fi=1, Web IP=2, Hold=4), command (0=query mode, 1=hold on, 2=hold off), request_id uint32 big-endian. При отсутствии Hold command/id=0.
Ответ 001c (encrypted write): 7 байт: version=1, request_id uint32 big-endian, result (0=success, 1=denied, 2=queue failure, 3=fault/timeout), hold_open (0/1). ID защищает UI от устаревшего ответа, явная установка состояния обеспечивает идемпотентность.
Порядок: защищённый proof → проверка владельца → запрос → hold/result → Wi-Fi или Web IP. Wi-Fi требует переподключения для получения нового IP после DHCP; реклама остаётся единой.
AUTO-proof использует прежний путь и прежний RSSI-порог. Служебный путь не вызывает автоматическое открытие/продление таймера А. Алгоритм автомата/таймеры, OTA, Wi-Fi, Web UI, scanner, стандартное BLE bonding/encryption сохраняются.
