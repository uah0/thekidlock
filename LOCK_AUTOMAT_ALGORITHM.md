# Алгоритм автомата замка

Автомат замка — это диспетчер, который получает события от Android и BLE, а затем решает, когда можно открыть или закрыть замок.

## Состояния простыми словами

### 1. Закрыт

Замок физически закрыт. Телефон может подать команду открыть или сначала «вооружить» автомат.

### 2. Вооружён

Автомат ждёт, когда телефон приблизится и сигнал RSSI станет достаточным.

### 3. Открыт

Замок открыт. Пока телефон рядом, время открытия по таймеру A продлевается.

### 4. Заблокировано повторное открытие

Замок уже закрылся после слишком долгого открытия. Это защита от постоянного открывания и закрывания около границы сигнала.

Пока действует эта блокировка, повторное автоматическое открытие запрещено.

## Как замок открывается

Есть три варианта.

### Обычная команда OPEN

1. Android отправляет команду открытия.
2. Автомат помечает открытие как разрешённое для последующего RSSI-контроля.
3. Если замок закрыт и блокировки повторного открытия нет, замок открывается.
4. Запускаются таймер A и ограничение максимального времени открытия.

### Команда ARM_OPEN

1. Android сообщает: «готовься открыть».
2. Замок остаётся закрытым.
3. Автомат ждёт сильный сигнал RSSI.
4. При достаточном сигнале замок открывается.

### Сильный RSSI

Если автомат уже вооружён, телефон подключён и RSSI выше порога открытия, замок открывается.

Если замок уже открыт, сильный RSSI обновляет время последнего хорошего сигнала.

## Как замок закрывается

Замок закрывается одним из двух способов.

### Таймер A

Если после последнего достаточного RSSI прошло больше `timer_a_ms`, замок закрывается.

Обычно это означает: телефон удалился или хороший сигнал больше не поступает.

После закрытия по таймеру A повторное открытие не блокируется.

### Ограничение долгого открытия

При открытии запускается отдельный предел `long_open_ms`.

Если этот предел закончился раньше таймера A:

1. замок закрывается;
2. включается блокировка повторного открытия;
3. автомат ждёт подтверждённого удаления телефона;
4. только после этого блокировка снимается.

Этот механизм не даёт замку бесконечно открываться, если телефон долго находится рядом.

## Таймер Б и снятие блокировки

Таймер Б используется только после закрытия с блокировкой повторного открытия.

### По слабому RSSI

1. ESP32 получает слабый RSSI.
2. Слабый RSSI должен прийти подряд минимум три раза.
3. После трёх последовательных слабых измерений запускается таймер Б.
4. Если в это время снова пришёл сильный RSSI, таймер Б отменяется.
5. Если слабый сигнал сохраняется до конца таймера Б, блокировка снимается.

Один хороший пакет RSSI сбрасывает счётчик слабых пакетов.

### При разрыве BLE

Если телефон отключился, а блокировка уже действует:

1. запускается таймер Б;
2. при `timer_b_s == 0` блокировка снимается сразу;
3. иначе блокировка снимается после окончания таймера Б.

Обычный разрыв BLE, когда блокировки нет, сам по себе замок не открывает и не закрывает.

## Особые команды

### CLOSE

Команда закрывает замок сразу, если он открыт, и отменяет ожидание автоматического открытия.

### TEST_OPEN

Администраторская тестовая команда открывает замок даже при действующей блокировке повторного открытия.

Она не включает автоматическое повторное открытие по RSSI.

## Что делает Android, а что ESP32

Android:

- подключается по BLE;
- передаёт команды;
- передаёт информацию о наличии и силе сигнала;
- показывает состояние пользователю.

ESP32:

- хранит состояние автомата;
- проверяет блокировки и таймеры;
- принимает окончательное решение;
- передаёт команду ULP;
- контролирует физический результат.

Android не управляет катушкой напрямую.

## Схема переходов

```text
                 ARM_OPEN
                    |
                    v
              [ ВООРУЖЁН ]
                    |
          сильный RSSI и нет блокировки
                    v
[ ЗАКРЫТ ] <---- [ ОТКРЫТ ]
    ^               |
    |               |
    |       таймер A или long_open_ms
    |               v
    |       [ ЗАКРЫТ + БЛОКИРОВКА ]
    |               |
    |       3 слабых RSSI / BLE disconnect
    |               v
    +--------- таймер Б истёк
```

Главное правило: телефон предлагает действие, но последнее слово всегда остаётся за автоматом ESP32.
