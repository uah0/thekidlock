# Журнал изменений Android-приложения

## Обновление IP Web UI при каждой кнопке «Настройки» — 04.10.2026

- При нажатии приложение запрашивает свежий IP ESP32 по encrypted BLE и больше не открывает сохранённый адрес из домашней Wi-Fi сети.
- Если адрес не пришёл за 5 секунд, приложение создаёт LocalOnlyHotspot. ESP получает Wi-Fi параметры через BLE, подключается и передаёт IP hotspot обратно; Chrome открывает актуальный Web UI.
- Redmi Note 15 runtime PASS без домашнего Wi-Fi: hotspot `172.18.51.2`, IP ESP `172.18.51.177`, firmware 10.0.314. Android build 182 и debug/release unit tests прошли.

## Получение Web UI IP от ESP — 04.10.2026

- Добавлена encrypted PhoneBeacon характеристика для IPv4, передаваемого ESP. Корректный адрес сохраняется в `lock_wifi_ip` и передаётся экрану через broadcast.
- Кнопка открывает только свежеполученный IP; если его нет, приложение 5 секунд ждёт BLE push и затем включает существующую точку доступа с Wi-Fi provisioning.
- Для BLE markers `0x81`/`0x82` ESP игнорирует RSSI-порог открытия; обычный режим lock beacon не менялся.
- Android build 182 установлен, debug/release unit tests прошли; ESP 10.0.314 прошита OTA. Runtime IP push по домашней сети и через hotspot телефона подтверждены.

## Открытие Web UI по кнопке «Настройки» — 04.10.2026

- Исправлен неработающий статусный BLE маршрут: service отклоняет legacy Android Central connect, поэтому кнопка больше не запускает provisioning hotspot и не ждёт несуществующий `OTA_STATUS`.
- При первом нажатии приложение запрашивает IPv4 ESP32, проверяет и сохраняет его; последующие нажатия сразу открывают `http://<ip>/`.
- Android build 176 собран и установлен на Redmi Note 15; настройки ориентации `1/0` после установки восстановлены и проверены.
- Runtime проверка прошла: после первого ввода `192.168.1.54` Chrome открыл страницу замка «Мастер настройки»; значение IP сохранено для повторного открытия.
- Следующее нажатие открыло Web UI сразу, без диалога.

## Исправление Wi-Fi credentials long read — 04.10.2026

- Android и ESP сохраняют существующий length-prefixed credentials payload, но передают его блоками по 20 байт через пять encrypted bonded GATT characteristics. Это исключает проблемный offset 22 длинного чтения.
- В лог добавлены только размеры полей и индекс NUL исходного byte array; значение credentials не выводится.
- Кнопка «Настройки» сохраняет активный Web UI запрос, проверяет `WEB_READY` по текущему BLE соединению до создания hotspot и не отменяет запрос при штатном отключении после чтения credentials.
- `MainActivity` подключает `OTA_STATUS` polling к pending-запросу; физическая установка Android build 175 выполнена с восстановлением экранной ориентации.

## Proof во время Wi-Fi provisioning — 04.10.2026

- `PhoneBeacon` теперь выдаёт encrypted proof bonded peer как при включённом Auto Open, так и в активном Wi-Fi provisioning. Вне provisioning Auto Open OFF по-прежнему запрещает proof; системное encrypted permission и проверка `BOND_BONDED` сохранены.
- `build-android.ps1`: PASS, debug APK build 171. APK установлена на Redmi Note 15; ориентация до/после сохранена и проверена (`accelerometer_rotation=0`, `user_rotation=0`).
- Runtime-проверка на кнопке «Настройки» ожидает разблокировки телефона.

## Восстановление зависшего BLE autoConnect — 01.10.2026

- Build 132: после 90 секунд без события подключения нативный запрос к сохранённому bonded-замку заменяется одной прямой GATT-попыткой. Её штатный таймаут оставлен 8 секунд; затем сервис повторяет нативный запрос.
- Повторное ожидание после GATT-разрыва контролируется тем же таймером. Если OPEN уже отправлен для текущего присутствия, прямой запрос не запускается.

## Исправление BLE-обнаружения на Xiaomi — 28.09.2026

- Убран аппаратный `ScanFilter` для основного поиска замка: Xiaomi не возвращал
  приложению совпадающую рекламу по 128-битному UUID. Поиск принимает BLE-пакеты,
  а соединение разрешается только если в записи рекламы есть UUID замка.
- Build 112 установлен на Xiaomi 2510DRA23E. Logcat подтвердил рекламу и
  `GATT_CONNECTED`; замок подтвердил защищённое bonded-соединение.

## Owner-сессия BLE и один сигнал рекламы — 28.09.2026

- При выключенном AUTO приложение инициирует BLE-соединение при запуске.
- Успешное защищённое чтение `ADMIN_STATE` подтверждает телефон владельца;
  только на нём показывается кнопка Web UI «Настройки».
- Owner-сессия сохраняется в foreground service и восстанавливается после
  перезапуска приложения/телефона, даже когда AUTO выключен.
- Оставлен только звуковой beep при обнаружении BLE-рекламы замка; сигналы
  слабого RSSI, подключения и отключения убраны.
- Android build 111 через проектный `build-android.ps1` — успешно.

## Закрытие замка при отключении Always Open — 28.09.2026

- При выключении подтверждённого Always Open теперь отправляется команда
  `AUTO_OFF_CLOSE`, которая явно запрашивает закрытие замка; ранее отправлялся
  только `MODE_AUTO`, сохранявший открытый запрос.
- Повторное нажатие самой кнопки Always Open выключает и сохраняет выключенное
  автооткрытие; переход через AUTO закрывает замок и затем включает автомат.
- Добавлен reducer test для выхода в AUTO через кнопку Always Open и кнопку AUTO.
- Android build 106 установлен на Xiaomi 2510DRA23E.
- После фактического `LOCKED` при сбросе Always Open очищается native presence
  latch; повторное включение AUTO может отправить новую команду OPEN.
- Фактический прогон подтвердил включение Always Open (`OPEN_HOLD`) и сброс
  с закрытием (`LOCKED`). Сборка 107 установлена.
- Полный прогон build 107 подтвердил AUTO (`OPEN`) → Always Open (`OPEN_HOLD`)
  → сброс (`LOCKED`) → AUTO (`OPEN`) → AUTO off (`LOCKED`); замок оставался
  закрытым при RSSI телефона `-38 dBm`.

## Повторное автооткрытие при непрерывном присутствии — 28.09.2026

- Presence guard теперь устанавливается только успешной записью `OPEN`, а не
  любым успешным GATT write (например `MODE_ALWAYS` или `AUTO_OFF_CLOSE`).
- Автооткрытие снова разрешается, когда замок подтвердил `OPEN`, а затем
  `LOCKED`, даже если телефон остался рядом. Старый `LOCKED` до открытия не
  сбрасывает guard; native auto-connect latch синхронно очищается.
- Добавлены unit tests на stale/повторные status и нормализацию статусов.
- Сборка 103 установлена на Xiaomi 2510DRA23E; настройки ориентации `0/0`
  восстановлены после установки.

## Диагностика автооткрытия — 28.09.2026

- Добавлен ограниченный по частоте лог причины подавления повторной команды
  AUTO. Он показывает service mode, RSSI-порог и native presence latch.
- Поведение команд замка и алгоритм повторного открытия не менялись.
- Диагностическая сборка 101 установлена на Xiaomi 2510DRA23E.

## Подтверждённые режимы главного экрана — 28.09.2026

- Две mode-кнопки теперь отображают только подтверждённое состояние замка и
  Android BLE-сервиса. Намерение пользователя и отправка команды хранятся как
  отдельный pending-переход.
- После `OPEN_HOLD` подтверждается Always Open; после `OPEN`/`LOCKED`
  подтверждается обычный режим. AUTO подсвечивается только при подтверждённом
  обычном режиме замка и активном automatic service.
- Добавлен read-only snapshot режима сервиса при bind. Timeout, disconnect,
  несовместимые status и отказ записи обрабатываются без спекулятивного
  подсвечивания запрошенного режима.
- Reducer централизовал состояние и эффекты; удалены прежние mode-флаги из
  `MainActivity`.
- Debug APK сборки 100 установлен на Xiaomi 2510DRA23E.

## Удаление настройки «Долго открыт» — 28.09.2026

- Удалено поле таймера из административной панели и из привязки к BLE admin
  schema. Зарезервированное поле legacy CSV сохраняется для совместимости.

## Активный scan без таймаута пустого поиска — 28.09.2026

- Убран останов `LOW_LATENCY`-сканирования через 15 секунд без подходящего
  результата. Scan остаётся зарегистрированным до объявления замка или
  ошибки BLE API, устраняя собственные циклические слепые окна.
- Service UUID и порог RSSI не менялись. GATT error recovery и departure scan
  не менялись.

## Настройка паузы восстановления BLE security — 27.09.2026

- На экране ползунка порога подключения добавлен соседний вертикальный ползунок
  защитной паузы BLE, диапазон 0…2000 мс с шагом 50 мс.
- Значение по умолчанию — 700 мс; оно сохраняется в настройках телефона и
  используется `BleRepository` перед защищёнными GATT-операциями.

## Фоновое BLE-обнаружение замка — 26.09.2026

- AUTO использует UUID-filtered `BluetoothLeScanner` PendingIntent scan с
  `SCAN_MODE_LOW_POWER`; callback `LOW_LATENCY` scan не используется для
  ожидания отсутствующего замка.
- Результат проверяется по Service UUID и времени; повторные scan intents
  отсекаются gate до завершения присутствия/ошибки GATT.
- При обнаружении сервис подключается напрямую к `BluetoothDevice` из
  `ScanResult`, затем выполняет прежние bonding/authentication и `OPEN`.
- Сохранена отдельная BALANCED scan-фаза `waitForDeparture()` для защиты от
  повторного открытия до ухода пользователя.
- Добавлен лог `GATT_CONNECTED`; ошибки старта активного flow отличаются от
  логов подавления дубликатов.
- 15-секундный LOW_LATENCY timeout и reconnect backoff остались только в
  отдельном ADMIN/UI discovery/recovery flow.
- Удалён таймер departure recovery, который мог запускать LOW_LATENCY поиск без
  нового BLE advertisement; сохранена специализированная проверка ухода.

## Однократное выключение AUTO — 25.09.2026

- После первой команды `AUTO_OFF_CLOSE` сервис принимает фактический статус
  замка и не повторяет закрытие до `LOCKED`.
- При статусе `OPEN` управление остаётся доступно; успешное закрытие отдельно
  отмечается по статусу `LOCKED`.

## Стабильный вид главных кнопок — 25.09.2026

  подтверждения выключения AUTO.
- Ограничение на команды в состоянии `OPEN_SENT` сохранено.

## Версия приложения над политикой конфиденциальности — 25.09.2026

- Для ссылок и содержимого настроек зарезервировано место под этот блок.

## Автоматическое отключение точки доступа — 19.08.2026

- После запуска LocalOnlyHotspot приложение запоминает первый IP ESP32.
- Каждые 15 секунд IP повторно читается по BLE.
- Если IP изменился, точка доступа телефона закрывается: ESP32, вероятно,
  перешёл в другую Wi-Fi сеть.
- Если ESP32 не сообщил IP за 15 секунд, точка доступа также закрывается.

## Автоматическое подключение к Web UI — 19.08.2026

- Убрана отдельная кнопка запуска точки доступа из панели настроек.
- Кнопка «Подключиться к Web UI» теперь находится в общей панели телефона и
  отображается независимо от видимости административного блока.
- При нажатии приложение сначала читает по BLE текущий статус Web UI и IP ESP32.
- Если IP отсутствует, приложение автоматически создаёт локальную точку доступа,
  передаёт её SSID и пароль по BLE и открывает Web UI после получения IP.

- Android больше не разрывает соединение по своему RSSI-порогу.
- Поиск замка переведён на UUID сервиса без ограничения сохранённым MAC-адресом.

## Удаление ADMIN_AUTH

- Удалены поле пароля, кнопка входа и UUID `ADMIN_AUTH`.
- Кнопки чтения и сохранения доступны зарегистрированному телефону в READY.
- APK успешно пересобран.

## Исправление запуска реактивного Pairing

- После discovery незарегистрированный телефон теперь читает защищённую
  `LOCK_INFO`, что запускает единственный системный SMP Pairing Android.
- Явный `createBond()` не возвращён, поэтому прежняя гонка двух инициаторов и
  двойной диалог Pairing исключены.
- Успешный Pairing подтверждён пользователем на реальном телефоне.

## A5.2 — BLE-панель настроек

- В Android возвращён фактически используемый прошивкой UUID `ADMIN_AUTH`.
- Добавлен ввод пароля без сохранения, AUTH и автоматическое чтение настроек.
- Добавлены поля RSSI открытия, RSSI удержания, двух таймеров, GPIO бипера и
  активного уровня GPIO замка.
- Чтение и сохранение доступны только после успешной AUTH в текущем соединении.
- Debug APK успешно собран offline.

## Изменение модели доступа к настройкам

- Отдельная парольная AUTH удалена по решению пользователя.
- Настройки доступны после стандартного encrypted + bonded BLE-соединения.
- Android-панель больше не запрашивает пароль и сразу читает/сохраняет
  конфигурацию после Pairing.

## Исправление первой неудачной попытки Pairing

- Устранена гонка между остановкой Foreground Service и ручным GATT scan.
- Ручное подключение запускается через 700 мс после прямой остановки сервиса.

## Защита ручной регистрации от второго GATT-клиента

- Перед ручным поиском и Pairing Activity теперь принудительно останавливает
  Foreground Service автооткрытия.
- В процессе регистрации остаётся ровно один GATT-клиент и один SMP-сеанс.

## Исправление двойного Pairing

- Убран повторный вызов Android `BluetoothDevice.createBond()`.
- ESP32 остаётся единственным инициатором SMP Pairing/Bonding.
- Android теперь ждёт системное событие bond и после него повторяет защищённое
  чтение GATT.
- Повторные два диалога подтверждения Pairing устранены на уровне протокола.

## Исправление окна регистрации

- Web-команда регистрации теперь освобождает текущее BLE-соединение при лимите
  одного connection и возвращает advertising для нового телефона.

## A5.1 — BLE admin protocol

- В ESP32 добавлены encrypted characteristics `ADMIN_AUTH` (.0005) и
  `ADMIN_CONFIG` (.0006).
- `ADMIN_AUTH` принимает compile-time пароль администратора только от encrypted
  bonded соединения.
- После успешной AUTH на время соединения разрешено чтение/запись конфигурации.
- Формат конфигурации: `rssi,long_open_ms,timer_a_ms,buzzer_gpio,open_level`.
- Изменения проходят через NVS, `buzzer_set_gpio` и `lock_control`; GPIO из GATT
  напрямую не управляется.
- Android-протокол дополнен UUID этих характеристик; экран настроек будет
  подключён следующим подэтапом.

## Исправление BOOT_COMPLETED

- Убран отложенный `Handler` из `BootReceiver`: Android мог завершить процесс
  после `onReceive`, не выполнив запуск через 10 секунд.
- Foreground Service теперь запускается непосредственно во время
  `BOOT_COMPLETED`; задержки и повторные попытки выполняются внутри сервиса.
- Аппаратная проверка на Android 16 пройдена: после перезагрузки замок
  автоматически управляется из фона.

## Исправление запуска после выдачи разрешений

- Автооткрытие запускается сразу после успешной выдачи BLE/notification
  permissions.
- Повторное нажатие кнопки разрешений при уже выданных разрешениях запускает
  Foreground Service и не требует открытия других экранов.

## Исправление автозапуска после перезагрузки

- `BootReceiver` теперь обрабатывает `BOOT_COMPLETED` и `MY_PACKAGE_REPLACED`.
- Запуск Foreground Service выполняется явным package intent через 10 секунд
  после загрузки, когда Bluetooth успевает инициализироваться.
- Настройка автооткрытия сохраняется через `commit`, чтобы не потеряться при
  немедленной перезагрузке.

## A3 — фоновый Foreground Service

- Добавлен `BleLockService` с постоянным уведомлением и типом
  `connectedDevice`.
- Переключатель автооткрытия запускает/останавливает сервис.
- После boot сервис восстанавливается при сохранённой настройке.
- После READY отправляется только одна команда OPEN за цикл присутствия.
- После отключения сервис ждёт подтверждённого ухода по BLE scan и только затем
  разрешает новый цикл открытия.
- Добавлены ограниченные повторные попытки подключения и действие остановки в
  уведомлении.

## A2 — ручное BLE-подключение и OPEN

- Добавлен `BleRepository` с последовательностью scan, connect, service
  discovery, системный bonding и защищённое чтение.
- Scan фильтруется по service UUID и завершается через 15 секунд.
- Приложение читает LOCK_INFO и LOCK_STATUS и показывает их на экране.
- Кнопка «Открыть сейчас» записывает ASCII `OPEN` только в состоянии READY.
- Добавлены журнал состояний и сообщения GATT-ошибок.
- Добавлен `build-local.ps1` для самостоятельной offline-сборки через JDK 17 и

## Hotspot IPv4 через защищённый PhoneBeacon — Android этап (02.10.2026)

## HOTSPOT_IP — завершение Android/ESP (02.10.2026)

- Android IPv4 lookup использует перечисление поднятых интерфейсов и адресов. В первую очередь рассматриваются интерфейсы с AP-названием `ap*`, `softap*`, `swlan*`; единственный `wlan*` кандидат допускается только если нет активной Wi-Fi station сети. Адреса loopback/link-local/multicast/unspecified/broadcast отбрасываются. Неоднозначность возвращает «нет данных» и сохраняет credential/DHCP fallback. Стандартный Android API не раскрывает стабильно имя SoftAP интерфейса, поэтому физическое подтверждение на целевой модели остаётся необходимым.
- GATT characteristic: `HOTSPOT_IP_UUID = 6f4f0014-9a7b-4c21-8d32-5e6f708192a3`, в существующем PhoneBeacon service; 4 bytes IPv4 network-order, `00 00 00 00` означает отсутствие IP.
- Android проверяет `device.bondState == BOND_BONDED`; characteristic имеет `PERMISSION_READ_ENCRYPTED`, так что enforcement шифрования остаётся системному Bluetooth stack. IP очищается по жизненному циклу reservation; session token не даёт позднему STOP старого hotspot очистить адрес новой сессии.
- ESP использует единственный исходящий GATT connection: `connect → encrypted/bonded proof BLE_LOCK_V1 → Wi-Fi credentials → HOTSPOT_IP`. IP читается только при provisioning marker `0x81`; обычный AUTO proof не делает дополнительного чтения и соединения.
- ESP проверяет unicast IPv4, хранит его только в RAM через `wifi_ota_set_runtime_phone_ip()` / `wifi_ota_get_runtime_phone_ip()`. На IP отсутствует/ошибке продолжается credential provisioning fallback. ESP DHCP/static-IP поведение не менялось; NVS не получает IP телефона.
- Android `build-android.ps1 -Action test`: PASS, build 153 (debug/release и unit tests). ESP `build-esp32.ps1`: PASS, firmware 10.0.275; OTA PASS, device-agent подтвердил `10.0.274 → 10.0.275`.
- Радио-тест характеристик на физическом телефоне и проверка фактического интерфейса hotspot не выполнялись. Resolver покрыт unit tests, но использует доступные интерфейсы Android и при ambiguity намеренно возвращает отсутствие адреса.
