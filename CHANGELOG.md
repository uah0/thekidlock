# Журнал изменений

## Диагностический ADC GPIO7 при постоянно включённом MOSFET — 30.09.2026

- Добавлены Agent-команды `ulp_gate_test` и `ulp_gate_test_stop`. Тест разрешён
  только в `OPEN_HOLD`; GPIO9 автоматически выключается через 5 секунд или по
  команде остановки.
- Пока GPIO9 HIGH, ULP считывает raw ADC1_CH6/GPIO7 каждые 40 мс и публикует
  значение в существующем `sense_raw`; диагностический FSM отдельно обозначен
  как `Диагностика GPIO7: MOSFET включён`.
- `build-esp32.ps1`: PASS, firmware 10.0.236, app image 0x1472e0,
  свободно 32% OTA-раздела. OTA и возврат устройства 10.0.235 → 10.0.236
  подтверждены; диагностический запуск дал raw GPIO7 55–68.
- После подтверждения щупом 2.08 В непосредственно на GPIO7 добавлен второй
  диагностический срез: первое raw-чтение сравнивается со средним следующих
  восьми чтений с паузой 100 мкс. Сборка 10.0.237 (image 0x147340) прошла;
  OTA 10.0.236 → 10.0.237 подтверждён на том же устройстве. В FSM GATE_TEST
  получены первое чтение 56–63 и среднее серии 22–34 raw; после теста ULP
  вернулся в OPEN_HOLD, `fault_flags=0`.

## Android: закрытие при выходе из Always Open — 28.09.2026

- При выключении Always Open Android отправляет `AUTO_OFF_CLOSE`, чтобы замок
  сразу получил запрос закрытия; переход в обычный AUTO подтверждается через
  фактический `LOCK_STATUS`.
- Сброс Always Open выключает и сохраняет автооткрытие; явный выбор AUTO
  закрывает замок перед возобновлением автоматического открытия.
- Добавлен тест reducer-а для выключения Always Open обеими mode-кнопками.
- Проверено на телефоне: Always Open дал `OPEN_HOLD`, сброс дал `LOCKED`.
  Добавлена очистка native presence latch после закрытия; APK build 107 установлен.
- Полный прогон build 107 подтвердил AUTO (`OPEN`) → Always Open (`OPEN_HOLD`)
  → сброс (`LOCKED`) → AUTO (`OPEN`) → AUTO off (`LOCKED`); в конце замок
  оставался закрытым при телефоне рядом.

## RSSI-контроль и удаление «Долго открыт» — 28.09.2026

- `phone_rssi_threshold` больше не проверяется повторно при записи команды
  `OPEN`; там остаётся проверка encrypted/bonded. Порог применяется в RSSI
  мониторе зоны, который отключает соединение после `zone_exit_grace_ms`.
- Удалены настройка `long_open_s`, её обычные дедлайны и поле из ESP Web UI и
  BLE admin-схемы. Старые NVS-ключи удаляются при запуске/сохранении конфига.
- Сохранён отдельный фиксированный 10-секундный ручной тест открытия.
- Android admin UI также больше не показывает удалённую настройку; legacy BLE
  CSV сохраняет зарезервированное поле для совместимости старых клиентов.

## Android: непрерывное ожидание BLE-рекламы — 28.09.2026

- Убран внутренний 15-секундный timeout `LOW_LATENCY` discovery scan, чтобы
  отсутствие подходящего результата не завершало скан и не запускало
  backoff-слепое окно до 30 секунд.
- APK собран и установлен на Xiaomi 2510DRA23E. При включённом экране scan
  работает непрерывно; после выключения экрана Xiaomi сам приостанавливает scan.

## Удалены GPIO8-импульсы во время BLE-рекламы — 28.09.2026

- Удалены одиночный и повторяющийся запросы 50-мс импульса GPIO8, связанные с
  запуском/активностью BLE-рекламы.
- Другие сигналы buzzer-task (ручной тест и диагностика ошибки закрытия) оставлены.
- Advertising, BLE-параметры и алгоритм замка не изменялись.

## Настройка выдержки выхода из BLE-зоны — 27.09.2026

- В настройки замка Web UI добавлена выдержка слабого RSSI перед разрывом BLE;
  диапазон 0…10000 мс, значение по умолчанию 1500 мс.
- Значение сохраняется в NVS (`zone_exit_ms`) и применяется BLE-задачей
  при текущей сессии без перезапуска. Ноль означает отключение на первой
  проверке RSSI ниже порога.
- `/api/config` возвращает новую настройку; старые POST без неё сохраняют
  текущее значение. BLE admin CSV не менялся.
- Проверка OTA устройства выявила ограничение длины NVS key; сохранение
  использует короткий ключ `zone_exit_ms`, внешний параметр API не менялся.

## BLE Security: возврат допуска Legacy Pairing — 27.09.2026

- `sm_sc_only` возвращён с `1` на прежнее значение `0`; Secure Connections
  остаётся включён (`sm_sc=1`), но Legacy Pairing fallback снова разрешён.
- Удалён диагностический лог, указывавший SC-only; остальные настройки
  безопасности и bonding не менялись.

## NimBLE: разрешён только LE Secure Connections — 26.09.2026

- Включён `sm_sc_only=1`, чтобы peer без LE Secure Connections отклонялся без
  Legacy Pairing fallback. Остальные параметры bonding/security не менялись.
- При старте BLE добавлен serial log с bonding, SC, SC-only и MITM значениями.

## BLE multi-slot — этап 1, лимиты NimBLE — 26.09.2026

- Увеличен лимит NimBLE-соединений с 1 до 6 и controller BLE activities с 6 до 7
  (6 соединений и одна рекламная активность). Прикладная логика BLE пока не менялась.

## BLE multi-slot — этап 2, таблица соединений — 26.09.2026

- Состояние RSSI, security и регистрации перенесено из singleton-полей в таблицу
  слотов. `OPEN` использует RSSI своего соединения; сигналы для lock-control
  агрегируются, а потеря одного secured-соединения не сбрасывает остальные.

## BLE multi-slot — этапы 3–4, владелец и реклама — 26.09.2026

- Слот 0 зарезервирован за владельцем, гостям доступны только слоты 1–5. При
  первом pairing owner-соединение переносится из временного guest slot в слот 0;
  повторное параллельное owner-соединение отклоняется.
- Реклама запускается, пока свободен хотя бы один слот, и останавливается, когда
  заняты все шесть. Accept-list остаётся общим и не менялся.

## BLE multi-slot — этап 5, admission grace для гостей — 26.09.2026

- Слабый гостевой слот освобождается после 1500 мс валидной медианы ниже общего
  порога открытия. Слот владельца исключён; старый 6000 мс BLE disconnect grace
  сохранён отдельно. При RSSI не ниже порога или открытой/удерживаемой двери новый
  отсчёт не запускается.

## BLE multi-slot — этап 6, диагностика слотов — 26.09.2026

- В существующий RSSI task добавлен периодический `ESP_LOGI` с индексом слота,
  owner flag, handle, последним RSSI и временем слабого гостевого сигнала.
- Финальная прошивка с проверенными типами аргументов логов: `10.0.200`.

## Отключение импульсной проверки зазора при постоянном открытии — 26.09.2026

- В ULP добавлен отдельный `ULP_CMD_HOLD_OPEN`. В этом режиме gate удерживается
  LOW, импульсное измерение зазора пропускается, `pulse_actual_us` публикуется
  как 0.
- Состояние восстанавливается из NVS после перезагрузки и возвращается к
  обычному измерению при выключении режима.
- При переходе из LOCKED в постоянное открытие сохраняется проверка снятия
  остаточного тока, но после неё импульсное измерение не выполняется.
- Обычный OPEN, таймеры, закрытие и финальная проверка закрытия не изменены.

## Завершение выключения AUTO при открытой двери — 25.09.2026

- Повторный `AUTO_OFF_CLOSE` прекращается после первого статуса замка;
  оставшийся открытым замок больше не блокирует дальнейшее управление.

## Стабильный вид кнопок при выключении AUTO — 25.09.2026

- Убран переход прозрачности главных кнопок при каждом кратком статусе
  `OPEN_SENT`; блокировка команд во время записи сохранена.

## Версия Android в приложении — 25.09.2026

- Удалены передача Android-версии в URL Web UI и её отображение в Web UI.
- Над строкой «Политика конфиденциальности» отображаются версия, номер сборки
  и дата со временем сборки Android-приложения.

## Закрытие по одному листу и имя телефона — 24.09.2026

- ULP начинает 300-мс притяжку только при полном контакте или
  зазоре в один лист; «зазор 2» больше не запускает закрытие.
- Сохранена цепочка 300 мс ON → 100 мс OFF → диагностика; постоянное
  питание включается только при подтверждённом отсутствии зазора.
- Из мастера удалён тест с двумя листами; служебная точка рассчитывается
  из контакта и одного листа.
- Android автоматически пишет имя телефона в ESP при защищённом
  handshake; reboot после нового pairing отложен на 8 секунд.

## Сохранение `ALWAYS_OPEN` и синхронизация Android — 24.09.2026

- ESP32 хранит режим `AUTO/ALWAYS_OPEN` в NVS и восстанавливает его
  после перезагрузки.
- `/api/status` публикует явный флаг `hold_open`.
- Android при выборе автоматики сначала посылает `MODE_AUTO`,
  проверяет `LOCK_STATUS` и только после этого возобновляет автоматическое
  открытие.
- Кнопка «Автоматический режим» учитывает фактический флаг
  сервиса и подтверждённый `OPEN_HOLD`.

## GPIO5 в закрытом состоянии — 24.09.2026

- ULP теперь обновляет напряжение GPIO5 и в `LOCK_STATE_LOCKED`.
- Замер не переключает GPIO9, не выключает соленоид и не запускает
  диагностику зазора.

## Напряжение аккумулятора в Web UI — 24.09.2026

- В панель «Соленоид и положение пластины» добавлено напряжение
  одной Li-ion ячейки, измеряемое GPIO5.
- `/api/ulp` отдаёт `battery_mv`, рассчитанный по штатной eFuse-калибровке
  ADC и делителю 150/27 кОм; сырой `vbat_raw` сохранён.

## Динамическая граница отсутствия зазора — 24.09.2026

- Граница «контакт / зазор 1» перенесена с 50% на 17% интервала между точками
  полного контакта и одного листа.
- В диагностическом API и Web UI показана вычисленная raw-граница.

## Пороги положения пластины в Web UI — 24.09.2026

- В панели «Соленоид и положение пластины» показаны пять сохранённых мастером
  точек калибровки АЦП и границы классификации контакта/зазоров ULP.

## Ударения в мастере калибровки — 24.09.2026

- Экранные инструкции отделены от реплик синтезатора речи.
- Во всех основных и корректирующих голосовых репликах расставлены ударения
  знаком Unicode `U+0301`; видимый текст остался без диакритики.

## Размещение автообновления — 24.09.2026

- Переключатель автоматического обновления перенесён из сетевых настроек в
  панель «Обновление прошивки» рядом с ручной загрузкой `.bin`.

## Автоматическое OTA по фиксированному адресу — 24.09.2026

- HTTPS URL прошивки удалён из Web UI и больше не передаётся Web API.
- Адрес latest release asset закреплён в `wifi_ota.c`.
- Добавлен сохраняемый переключатель автоматического обновления. При включении
  проверка выполняется сразу и при следующих запусках после подключения Wi-Fi.
- Автоматическая OTA сначала сравнивает дату/время сборки удалённого descriptor и
  не записывает образ, если он не новее текущего.

## Цвет сетевых полей Web UI — 24.09.2026

- Текст в полях SSID Wi-Fi и необязательного HTTPS-адреса прошивки сделан
  чёрным, включая отображение в WebKit/WebView.

## Управление зарегистрированными телефонами — 24.09.2026

- Массовое и одиночное удаление bonds теперь имеют одинаковые условия доступа;
  для «Удалить все телефоны» больше не требуется аппаратный режим настройки.
- При удалении активного bond его BLE-соединение немедленно помечается как
  неавторизованное и завершается стандартной GAP-командой.
- Web API списка bonds возвращает сохранённое имя телефона с корректным JSON-
  экранированием; Web-таблица показывает имя отдельной колонкой. Выходной JSON-
  буфер размещён в heap, чтобы большой список не переполнял стек HTTP-задачи.

## Настройки замка и аудит регистрации — 24.09.2026

- Из Web UI, BLE admin schema, конфигурации и автомата удалены изменяемые
  параметры GPIO замка и активного уровня; силовой GPIO9 остаётся аппаратной
  константой прошивки/ULP.
- «Долго открыт» переведён на единый контракт `long_open_s` в секундах
  (1–3600). Старое значение NVS в миллисекундах мигрирует с округлением вверх.
- При успешном сохранении удаляются устаревшие NVS-ключи аппаратных настроек.
- Выполнен аудит блока регистрации телефонов; выводы записаны в `AUDIT.md`.

## Сохранение таймера «Долго открыт» — 23.09.2026

- Исправлены недопустимо длинные имена NVS-ключей порогов BLE RSSI.
- Общая форма настроек больше не получает `ESP_ERR_NVS_KEY_TOO_LONG` при
  сохранении корректных значений.

## Событийные ULP-логи — 23.09.2026

- `ulp_gate` и `ulp_gap` в обычном режиме выводятся только при значимом
  изменении автомата, классификации, команды, ошибки или результата закрытия.
- Изменения счётчиков диагностических импульсов больше не засоряют журнал.
- Добавлен временный verbose-режим с прежней детализацией по фронтам GPIO9.
- В Agent API и клиент добавлены `diagnostics-on` и `diagnostics-off`.

## Удалённый UART monitor — 23.09.2026

- Добавлен общий перехват `ESP_LOG` через стандартный `esp_log_set_vprintf()` с
  сохранением прежнего UART-вывода.
- Последние 32 КиБ прикладного журнала хранятся только во внутренней RAM.
- Добавлен `/api/agent/monitor` с курсором, границей доступных данных и признаком
  вытеснения старого журнала.
- В `device-agent.ps1` добавлены одноразовый `log` и непрерывный `monitor`.

## Надёжный Wi-Fi после программного reset — 23.09.2026

- Wi-Fi обработчик теперь повторно вызывает `esp_wifi_connect()` после
  непреднамеренного `STA_DISCONNECTED`.
- Намеренное отключение при смене временных реквизитов не запускает обратное
  автоматическое подключение.
- Web restart, HTTP OTA и BLE reboot перед `esp_restart()` останавливают STA и
  дают драйверу 250 мс завершить работу.

## Приоритет домашней Wi-Fi сети — 23.09.2026

- Устранена гонка, при которой Android создавал точку телефона, пока ESP32 ещё
  подключалась к сохранённой домашней сети.
- ESP32 отклоняет временные BLE-реквизиты точки телефона при активном
  автоподключении к сохранённой сети.
- После фактического `ERROR_WIFI` временная точка телефона снова разрешается как
  аварийный способ открыть Web UI.

## Сохранение домашней Wi-Fi сети — 23.09.2026

- Сохранение SSID и пароля больше не требует заполненного HTTPS OTA URL.
- Пустой OTA URL разрешён; непустой адрес по-прежнему обязан начинаться с
  `https://`.
- Кнопка сохранения Wi-Fi теперь также сохраняет текущее состояние переключателя
  автоматического подключения и показывает ошибку, если эта запись не удалась.

## Полный тестовый Agent API и OTA по Wi-Fi — 23.09.2026

- В локальном тестовом API открыты все существующие команды автомата, прямые
  команды ULP `LOCK/UNLOCK`, тестовые шаблоны бипера и перезапуск.
- Добавлена загрузка собранного ESP32-образа через существующий HTTP OTA из
  `device-agent.ps1` с ожиданием повторного появления устройства и проверкой версии.
- Для первой OTA-прошивки поддержана старая прошивка без Agent API при явно
  заданном IP-адресе.
- GPIO9 оставлен в единоличном владении ULP; прямые команды ULP дают полный
  контроль силового автомата без конкурирующей записи из главного ядра.

## Локальная диагностика Codex — 23.09.2026

- Добавлен Agent API v1 с идентификацией устройства, списком возможностей и
  выдачей кольцевого журнала событий.
- Добавлена единая HTTP-команда с разрешёнными действиями `open`, `close`,
  `auto`, `always_open`; прямого управления GPIO нет.
- Добавлен проектный `device-agent.ps1` для обнаружения по ARP-кэшу, снимков,
  наблюдения, чтения событий и выполнения разрешённых команд.
- Последний адрес хранится в локальном игнорируемом каталоге `.device-agent`.

## Сигнал наложения управляющих событий — 23.09.2026

- Добавлен монотонный счётчик команд, наложенных на неподтверждённую команду ULP
  или активный отказ закрытия.
- Наложение имеет приоритетный звуковой код: тире 600 мс и три точки по 150 мс.
- Обычная серия зазора прерывается при появлении наложения; следующее наложение
  не теряется и создаёт новую аварийную последовательность.
- В UART добавлены `command_sequence`, `ack`, `overlap`, а для GPIO8 выводятся
  заданный и фактически прочитанный логический уровни.
- Счётчик наложений также доступен через `/api/ulp`.

## Защёлка отказа закрытия — 23.09.2026

- После неудачной контрольной проверки состояние зазора защёлкивается и новые
  силовые попытки на той же позиции пластины запрещаются.
- Повторное перевооружение выполняется только после достоверного `FAR` либо
  команды UNLOCK; первый замер `FAR` не может сразу включить соленоид.
- Бипер использует защёлку отказа, поэтому короткий переход состояния больше не
  может потерять звуковую серию.
- Граница `CONTACT/GAP_1` установлена в середине калибровочных эталонов:
  `ULP_FEATURE_CONTACT_MAX=10500`.
- Пауза без тока перед контрольным импульсом сохранена равной 100 мс.
- В `LOCKED` измерения зазора не выполняются; GPIO9 удерживается постоянно HIGH.

## Полная диагностика классификации зазора — 23.09.2026

- UART дополнен строками `ulp_gap` с ADC baseline/sense/delta, GPIO5 ADC,

## BLE больше не ждёт подключения Wi-Fi при загрузке

- Раньше `app_main()` вызывал `wifi_sta_start_and_wait()`, который блокировался
  (`portMAX_DELAY`) до получения IP по Wi-Fi, и только после этого стартовал
  `ble_phone_init()`. Если роутер после ребута отвечал медленно (сам ещё
  поднимается, DHCP не сразу отвечает, ретраи и т.п.), телефон физически не
  видел устройство по BLE всё это время — иногда около минуты и дольше.
- `wifi_sta_start_and_wait()` переименован в `wifi_sta_start()` и больше не
  блокируется: запускает Wi-Fi STA и сразу возвращается; подключение и
  переподключение продолжаются в фоне через уже существующий
  `wifi_event_handler` (лог о реальном подключении по-прежнему пишется).
- Порядок в `app_main()` изменён: `ble_phone_init()` теперь вызывается сразу
  после `lock_control_init()`/`buzzer_init()`, **до** старта Wi-Fi — телефон
  может открывать замок по BLE сразу после загрузки независимо от состояния
  Wi-Fi. `web_ui_start()` по-прежнему идёт после `wifi_sta_start()`, так как
  ему нужен инициализированный `esp_netif`/LWIP (это делает `wifi_sta_start()`),
  но не требует уже установленного соединения.

## Исправлен выбор порога RSSI при снятии блокировки

- Найдена реальная причина "мгновенного" снятия фиолетовой блокировки:
  `ble_phone.c` выбирал порог сравнения RSSI только по `lock_control_is_open()`.
  Пока замок заблокирован (`reopen_blocked`), он физически закрыт, поэтому
  код ошибочно брал строгий порог открытия (`phone_rssi_threshold`) вместо
  слабого порога удержания (`phone_rssi_hold_threshold`) — а именно слабый
  порог логически должен использоваться для решения "телефон достаточно
  ушёл, чтобы снять блокировку". Строгий порог менее отрицательный, поэтому
  срабатывал как "слабый сигнал" значительно чаще, создавая впечатление
  мгновенного сброса от одного сигнала.
- Добавлена `lock_control_is_blocked()` — потокобезопасный геттер текущего
  состояния `reopen_blocked` (раньше это было локальной переменной внутри
  задачи `lock_task` и не было видно снаружи модуля).
- `ble_phone.c` теперь использует слабый порог удержания, если замок либо
  открыт, либо заблокирован; строгий порог открытия — только когда замок
  закрыт и не заблокирован (обычное ожидание приближения телефона).

## Строгий счётчик снятия блокировки повторного открытия

- Счётчик слабого RSSI для снятия `reopen_blocked` сделан строго
  последовательным: любой один сильный (`RSSI_HIGH`) сбрасывает счётчик в 0;
  снятие блокировки требует ровно 3 подряд слабых отсчёта без перерыва.
- Убрано мгновенное снятие блокировки по событию BLE-дисконнекта. Раньше
  `LOCK_EVENT_DISCONNECTED` снимал блокировку по одному событию в обход
  правила "3 подряд" — а разрыв BLE-соединения не доказывает, что телефон
  физически ушёл (фоновый режим приложения, разрывы стека BLE и т.п. могут
  происходить, даже когда телефон лежит рядом с ридером). Теперь
  единственный путь снятия блокировки — строгий RSSI-счётчик.

- Добавлен watchdog повторного `requestMtu()`: отсутствие callback больше не оставляет приложение в `DISCOVERING` до системного 30-секундного тайм-аута; GATT быстро пересоздаётся.

## Восстановление BLE на ESP32 после зависшего соединения

- ESP32 удаляет устаревший connection handle, если NimBLE больше не находит это соединение, и сразу возобновляет рекламу.
- При недоступном RSSI дольше двух секунд ESP32 запрашивает штатный разрыв зависшей связи; запрос ограниченно повторяется до получения события disconnect.
- Добавлен watchdog остановленной BLE-рекламы при отсутствии активного соединения.

## Подсказка геолокации на Android 6–11

- При выключенной системной геолокации приложение объясняет требование BLE-сканирования Android 6–11 и предлагает открыть настройки.
- На Android 12 и новее это сообщение не выводится.

## Быстрое восстановление после выключения Bluetooth телефона

- ESP32 запрашивает трёхсекундный BLE supervision timeout, чтобы быстрее освобождать зависшее соединение и возобновлять рекламу после внезапного исчезновения радиоканала телефона.
- Android больше не оставляет `connectGatt()` зависшим на системные 30 секунд: попытка без callback пересоздаётся через 8 секунд.
- На Android 6–11 согласование увеличенного MTU перенесено после защищённого подключения и `READY`, поэтому оно больше не задерживает восстановление основных функций замка.
- После системного события Bluetooth ON восстановление начинается через 3 секунды, когда BLE/GATT Android 6–11 уже готов; зависшее первое защищённое чтение ограничено тремя секундами.
- Android 6–11 после перезапуска Bluetooth выполняет короткую подготовительную GATT-сессию и сразу переподключается для восстановления шифрования сохранённого bond.
- Подготовительная сессия закрывается только после подтверждённого GATT disconnect, чтобы ESP немедленно возобновила рекламу.
- Рабочая сессия после warm-up подключается напрямую к уже найденному bonded-замку и не ждёт повторного BLE-сканирования.
- Для Android 6–11 после включения Bluetooth используется одна рабочая сессия с восьмисекундной паузой на восстановление системного security-состояния; экспериментальный warm-up отключён.
- На всех версиях Android MTU 256 теперь согласовывается после защищённого `READY`; это устраняет цикл `MTU status=6` на Android 16.

При screen-off native auto-connect теперь тоже вызывает единственный BLE presence tone на первое соединение за присутствие замка. Дубли в том же присутствии подавляются; короткий timed partial wake lock удерживает CPU только на вывод сигнала.
