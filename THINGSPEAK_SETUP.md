# Настройка облачного управления

## ThingSpeak

Создать три **закрытых** обычных канала, включить поля:

| Канал | Поля | Доступ ESP |
|---|---|---|
| Журнал | field1 MAC замка; 2 инициатор; 3 событие; 4 источник; 5 UTC микросекунды; 6 ID; 7 результат; 8 uptime/boot | Read/Write API keys |
| Команды | field1 MAC; 2 ID; 3 операция; 4 expiry UTC seconds; 5 issued UTC seconds; 6 оператор | MQTT subscribe |
| Результаты | field1 ID; 2 результат; 3 состояние; 4 MAC; 5 UTC seconds; 6 fault flags | MQTT publish/subscribe |

Создать отдельный MQTT Device для замка. Разрешить только subscribe команд и publish/subscribe результатов. Получить MQTT Client ID, Username, Password — пароль устройства MQTT, не аккаунта MathWorks.

В существующей панели ThingSpeak Web UI заполнить канал журнала и его Read/Write API keys, каналы команд/результатов и MQTT credentials. Включить журнал, затем управление. Пустые ключ/пароль сохраняют прежнее значение. По умолчанию облако выключено. При непустой очереди канал журнала менять нельзя; при ожидающем результате нельзя менять каналы управления.

Панель открывается существующей кнопкой «Настройки» Android через служебный BLE-маяк/сеанс телефона. Правила доступа локального Web UI не менялись.

Статус показывает UTC, MQTT, очередь, потери и код состояния. waiting_time — ещё нет SNTP; https_delivery — доставка журнала не подтверждена; command_nvs — ошибка хранения, действие заблокировано; busy — предыдущий результат ожидает подтверждения подпиской.

## Отправка

Клиенту нужны Write API key **команд** и Read API key **результатов**. Секреты ESP клиенту не передавать.

Из корня проекта:

    C:\Espressif\tools\python\v5.4.4\venv\Scripts\python.exe .\tools\thingspeak-control.py open --mac a0:f2:62:f1:14:b8 --command-channel 123 --result-channel 456

Ключи запрашиваются скрытым вводом. Допустимы переменные окружения THINGSPEAK_COMMAND_WRITE_KEY и THINGSPEAK_RESULT_READ_KEY. Не передавать секреты аргументами командной строки. --dry-run выводит формат без отправки.

Действия: open — прежнее ручное открытие на 10 секунд; close — прежнее закрытие; hold_on — постоянно открыт; hold_off — обычный режим. При hold команда close возвращает hold_conflict. После hold_off действуют прежние таймеры. При AUTO-маяке рядом замок может снова открываться — прежнее поведение.

ID — UTC микросекунды клиента. Часы клиента синхронизировать; для нескольких отправителей нужен единый координатор возрастающих ID. Запрос без секретов сохраняется в .device-agent/cloud-client. --id N повторяет только исходную операцию и время из этого файла, физическое действие не повторяется. При истёкшем сроке сначала проверить канал результатов.

Клиент публикует через HTTPS, ESP получает команду MQTT TLS; ESP публикует результат MQTT TLS, клиент читает HTTPS. Android в этой задаче не менялся. Порт домашнего роутера открывать не требуется.

## Проверка и ограничения

ok означает подтверждённое состояние ULP и, для hold, сохранённый режим. Таймаут клиента — неизвестное выполнение. QoS 0 может потерять сообщение. ESP повторяет результат каждые 16 секунд до собственного подтверждения подпиской; клиент явно повторяет команду с тем же ID. Новая команда не принимается до подтверждения предыдущего результата.

Bulk журнал не вызывает MQTT-уведомления ThingSpeak; читать его HTTPS. **Время события — field5, а не created_at**. Микросекунды — формат, точность определяется SNTP. UTC-опора прошлого запуска без синхронизации невосстановима: такие события помечаются unsynced.

Очередь: 32 сохранённые записи плюс RAM. При длительном отсутствии облака возможны потери новых событий со счётчиком. Это диагностический журнал, не гарантия полного аудита при любом отказе. Внутренняя NVS ключей не зашифрована; Secure Boot/flash encryption/eFuse здесь не активировались. Локальный API по указанию пользователя не защищался.

После настройки проверить: UTC/MQTT → open/ok; hold_on/OPEN_HOLD; hold_off/обычный режим; close/LOCKED при отсутствии AUTO; журнал ID/field5; повтор ID без нового действия; просроченный/чужой target без действия; потерю сети/восстановление; reboot без повторного действия. До настройки каналов live-проверка не считается выполненной.
