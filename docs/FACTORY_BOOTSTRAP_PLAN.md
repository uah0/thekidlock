# Первоначальная прошивка нового замка и OTA с телефона

## Требование пользователя

Прошивка поступает в ESP только с телефона. Android обнаруживает опубликованную
сборку, скачивает encrypted OTA во внутреннее хранилище, уведомляет пользователя.
Установка на замок запускается только кнопкой «Установить обновление» в Web UI.
ESP не скачивает прошивку из интернета; домашний Wi-Fi сохраняется для других функций.

## Реализованный путь — 10.0.438

- Android выполняет HEAD/GET закреплённого GitHub latest URL и хранит образ
  в private files/firmware/ble_lock_stage1_s3.bin через AtomicFile.
- Проверка запускается через 10 секунд после открытия/возобновления приложения,
  затем через 6 часов; ошибка или активный hotspot откладывает проверку на 15 минут.
- Новизна cache определяется по HTTP-метаданным, а не сравнением версии замка.
  После успешного скачивания приложение показывает уведомление Toast.
  Проверка при полностью закрытом приложении как отдельная фоновая служба не реализована.
- Пользователь открывает «Настройки»; приложение создаёт локальную точку доступа,
  существующее защищённое BLE-соединение передаёт credentials и IP Web UI.
- WebView предоставляет private cache как /__app/firmware; нажатие кнопки
  отправляет encrypted файл POST /api/ota. Интернет ESP для передачи не нужен.
- ESP выполняет штатное decrypt/signature verification, запись другого OTA-раздела,
  reboot и OTA self-check. Прямой downloader удалён, auto_update запрещён.

## Исторический USB bootstrap 10.0.560

Для пустого ESP32-S3 локально подготовлен единый образ из bootloader, таблицы
разделов, OTA data и signed-dev приложения 10.0.560:
`archive/production/usb-bootstrap-10.0.560/thekidlock-usb-bootstrap-10.0.560.bin`.
Инструкция и manifest находятся рядом. Это профиль без записи eFuse, для flash
4 MB. В объединённом бинарном файле диапазон NVS заполнен `0xFF`, поэтому его
запись стирает прежнюю конфигурацию. Пакет предназначен для нового или сознательно
сброшенного устройства. Физическая запись через USB не выполнялась.

Этот bootstrap не включает аппаратную защиту Secure Boot/Flash Encryption Release
и не является завершённым защищённым factory образом. Его дальнейшее обновление
возможно через телефон, который скачивает зашифрованный OTA образ и передаёт его
по нажатию в Web UI.

## Что ещё требуется для пустого нового ESP

1. Согласовать NVS HMAC slot: текущая factory preparation использует KEY2,
   опубликованный finalize-existing — KEY4. Не использовать их как совместимые
   профили пустого нового устройства без подготовки.
2. Зарегистрировать телефон штатным физическим окном BLE и обеспечить
   первоначальную калибровку до установки финализирующего OTA либо подготовить
   профиль рабочей прошивки, допускающий первоначальную настройку.
3. Проверить новый замок отдельно. Разрешение eFuse/Secure Boot/Flash Encryption
   и отключения ROM/JTAG требуется на конкретное устройство и операцию;
   разрешение текущего замка на новые устройства не распространяется.

## Статус

Установка 10.0.438 с private cache телефона кнопкой проверена на текущем защищённом
замке. USB bootstrap 10.0.560 собран локально, но ещё не установлен на новом ESP.
Универсальный защищённый factory bootstrap пустого ESP пока не реализован.
Архитектура и алгоритмы открытия/таймеров сохраняются.

## Состояние на момент паузы — 13.10.2026

Последние опубликованные версии на GitHub:
- ESP: [esp-v10.0.560](https://github.com/uah0/thekidlock/releases/tag/esp-v10.0.560)
- Android: [app-v1.0.395](https://github.com/uah0/thekidlock/releases/tag/app-v1.0.395)

Локальный USB bootstrap 10.0.560: 1,511,424 байта, SHA-256
`e1719d40a34faa4c9a74152254e0eaaa4341f215122a0d8253ef27487bf6da7c`.
Передавать его через USB следует только на новый ESP32-S3 с flash 4 MB;
образ стирает NVS и не предназначен для восстановления текущего замка.

Работа остановлена по просьбе пользователя. Защищённый универсальный factory
профиль остаётся незавершённым. До отдельного указания на конкретную операцию
не включать eFuse, Secure Boot/Flash Encryption Release и не отключать ROM/JTAG.
Продолжить с проверки совместимости NVS HMAC slot и пути первичной регистрации
и калибровки нового устройства; сохранять возможность восстановления.

## Активный USB-образ — 13.10.2026

В `usb-bootstrap/` подготовлен единый signed-dev образ из текущей сборки
10.0.574: `thekidlock-usb-bootstrap.bin` (1 511 424 байта, SHA-256
`4dcb5ac4e840fb63ea7a02ffd8d259e7f78c8d39f9dbfe8e24d1608afb1734a8`).
Манифест содержит адреса и контрольные суммы всех компонентов; скрипт
`usb-bootstrap/build.ps1` позволяет повторить упаковку после новой сборки ESP.
Результат побайтово совпадает с объединением штатным `esptool merge_bin`.
NVS пуста, eFuse не изменяются. Физическая запись в новый чип ещё не выполнялась.

Это полный образ текущей прошивки с BLE-регистрацией владельца и калибровкой, а не
аппаратно защищённый factory-профиль. На момент подготовки образа на GitHub был
OTA 10.0.570; обновление через телефон требовало публикации версии выше 10.0.574.

## Двухэтапная USB-проверка — 13.10.2026

Проверочный USB-образ остаётся 10.0.574. Для испытания обновления через телефон
опубликован совместимый `signed-dev` OTA 10.0.578. После проверки собирается
универсальный USB-образ `usb-final/thekidlock-usb-final.bin` версии 10.0.581.
Весь NVS из первого этапа очищается; клиент выполняет регистрацию и настройку
заново. Снимок чипа не нужен: первый запуск создаёт индивидуальные ключи.

Образ 10.0.581 собран и проверен офлайн: NVS и раздел `nvs_keys` пустые, подпись
bootloader/app подтверждена, полный 4 MB файл совпал с `esptool merge_bin`.
Физически не записывался. Его первый запуск необратимо изменит eFuse и отключит
ROM Download, поэтому до записи требуется отдельное разрешение пользователя на
финальную защиту этого чипа.
