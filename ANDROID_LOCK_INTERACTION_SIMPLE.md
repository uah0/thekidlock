# Как Android взаимодействует с замком

Ниже описан алгоритм простыми словами.

## Кто участвует

- **ESP32** — маленький компьютер внутри замка.
- **Android** — приложение в телефоне.
- **BLE** — короткая радиосвязь между телефоном и ESP32.
- **RSSI** — оценка расстояния по силе радиосигнала.
- **ULP** — маленький помощник ESP32, который следит за состоянием замка и катушкой даже при малой активности основного процессора.

## 1. Телефон находит замок

1. ESP32 рекламирует себя по BLE.
2. Android ищет устройство с нужным именем и адресом.
3. Телефон подключается к ESP32.
4. Устройства договариваются о размере BLE-сообщений.
5. Android получает список BLE-сервисов и характеристик.

Если связь оборвалась, приложение ждёт и пытается подключиться снова.

## 2. Проверка телефона

Для обычного управления телефон должен быть зарегистрирован в замке.

При первом подключении выполняется сопряжение и регистрация телефона.

После этого ESP32 узнаёт телефон по защищённому BLE-соединению.

Телефон администратора дополнительно может:

- читать настройки;
- менять настройки;
- просматривать журнал;
- управлять зарегистрированными телефонами.

Обычный зарегистрированный телефон может управлять замком, но не должен менять административные настройки.

## 3. Телефон получает настройки

Android читает у ESP32 настройки замка.

ESP32 сначала передаёт декларативную схему — список доступных параметров. Например:

- порог сигнала для открытия;
- порог сигнала для удержания;
- время открытия;
- таймер A;
- таймер B;
- GPIO и уровень открытия;
- SSID Wi-Fi;
- URL прошивки.

Приложение не угадывает расположение параметров. Оно строит экран по полученному списку.

Если схема успешно получена, показывается динамическая панель.

Если схема повреждена или недоступна, Android показывает заранее подготовленную статическую панель.

## 4. Автоматический режим

Когда пользователь включает автоматическое управление:

1. Android поддерживает BLE-соединение с замком.
2. Телефон периодически измеряет силу сигнала.
3. ESP32 получает оценку RSSI.
4. ESP32 сравнивает RSSI с настройками.

Пример:

```text
RSSI открытия  = -68 dBm
RSSI удержания = -78 dBm
```

Чем число ближе к нулю, тем сигнал сильнее.

Если телефон достаточно близко и сигнал подходит для открытия, ESP32 запускает алгоритм открытия.

Если телефон удаляется и сигнал становится слабее порога удержания, ESP32 запускает алгоритм закрытия.

Важно: Android не управляет катушкой напрямую. Телефон только передаёт команду и данные о сигнале. Решение о фактическом открытии или закрытии принимает ESP32.

## 5. Ручное открытие

При нажатии кнопки открытия:

1. Android проверяет наличие BLE-соединения.
2. Android отправляет команду `OPEN`.
3. ESP32 принимает команду.
4. ESP32 проверяет состояние автомата, таймеры и разрешённость действия.
5. Если команда допустима, ESP32 передаёт её ULP-контроллеру.
6. ULP управляет выходом замка.
7. ESP32 контролирует результат и записывает событие в журнал.

Если команда не может быть выполнена, замок не меняет состояние и сообщает об ошибке.

## 6. Таймеры

После открытия замок работает по существующему алгоритму таймеров A и B.

Android не заменяет этот алгоритм. Он только показывает значения и может передать новые значения администраторской командой.

ESP32 самостоятельно:

- запускает таймеры;
- следит за временем;
- выполняет закрытие;
- обрабатывает конфликт команд.

## 7. Изменение настроек

Администратор изменяет поле в Android и нажимает сохранение.

Дальше происходит так:

1. Android проверяет диапазон и шаг числового значения.
2. Android формирует BLE-сообщение.
3. ESP32 проверяет формат и допустимость значения ещё раз.
4. ESP32 сохраняет настройку во внутреннюю память NVS.
5. ESP32 применяет настройку.
6. Android получает подтверждение.

Если BLE-соединение оборвалось или значение неверное, ESP32 не применяет неполную настройку.

## 8. Настройки Wi-Fi и OTA

Пароль Wi-Fi не возвращается в Android.

При чтении ESP32 передаёт только:

```text
имя Wi-Fi
URL сервера прошивки
```

Пароль остаётся внутри ESP32.

При сохранении:

- новый пароль можно передать явно;
- пустое поле пароля означает «оставить старый пароль»;
- если старого пароля нет, ESP32 отклоняет сохранение.

Сама прошивка скачивается по Wi-Fi. BLE используется только для чтения настроек и команды запуска OTA.

## 9. Что происходит при разрыве связи

Если BLE-связь пропала:

1. Android показывает потерю соединения.
2. ESP32 продолжает работать по своим правилам.
3. Замок не открывается только из-за исчезновения телефона.
4. Android пытается подключиться снова.
5. После подключения приложение снова читает состояние и RSSI.

Ошибки GATT означают, что конкретная BLE-операция не выполнилась. Это не обязательно означает неисправность замка.

## Короткая схема

```text
Android
   |
   | BLE: подключение, RSSI, команды, настройки
   v
ESP32
   |
   | проверка владельца, автомата и таймеров
   v
ULP-контроллер
   |
   | управление катушкой и контроль состояния
   v
Замок
```

Главное правило: Android просит, а ESP32 проверяет и принимает окончательное решение.
