# Настройка интернет-открытия

1. В приложении зарегистрированного телефона открыть «Настройки».
2. В панели MQTT указать адрес публичного брокера без схемы и номера порта. Логин, пароль, порт, топик и отдельный секрет MQTT вводить не нужно. Оба клиента используют обычный MQTT без TLS на фиксированном порту 1883.
3. Включить интернет-открытие и сохранить настройки. Текущее состояние соединения отображается в панели; кнопка проверки удалена. При ожидании UTC дать ESP доступ к интернету для SNTP.
4. Вернуться в приложение. Ещё раз открыть настройки из приложения, чтобы ESP передала телефону актуальные host/enabled и собственный ключ сопряжения. Затем вернуться на главный экран.
5. Нажать «Открыть через интернет». Телефон сначала подписывается на результат, затем отправляет подписанную команду. Bluetooth во время интернет-открытия не требуется.
6. Приложение сообщает фактическое открытие, ожидание пластины и фактическое закрытие. Команда отменяет «Постоянно открыт»; режим после цикла не восстанавливается. Повтор того же номера не перезапускает цикл.
7. После открытия ESP ждёт состояние «пластина убрана», максимум 20 секунд. Затем запрашивает закрытие. Если пластина отсутствует, штатное закрытие ждёт её возвращения; «ожидание пластины» не означает, что замок уже закрыт.

Топики автоматически формируются из Wi-Fi STA MAC: locks/a0f262f114b8/command и /result для текущего замка. Поля их редактирования нет.

HMAC применяется к назначению сообщения, идентификаторам замка/телефона, времени, номеру и действию/результату. Используется исходный LTK сопряжения этого телефона. Ключ не публикуется в MQTT, не показывается в Web UI и не записывается в логи. На Android пакет хранится зашифрованным Android Keystore; удаление записи телефона из замка отзывает его интернет-доступ.

Команда не передаётся открытым отдельным полем, но HMAC не является шифрованием: для одного известного действия содержание очевидно, а метаданные и результаты видны подписчикам и наблюдателям в сети. Общедоступный брокер не гарантирует доступность. При отсутствии подтверждения приложение сообщает об этом; повторять открытие автоматически нельзя.

Формат и поведение описаны в MQTT_DESIGN.md. Старый профиль команд ThingSpeak удалён; его HTTPS-журнал сохраняется. Порт роутера открывать не нужно.

Адрес брокера по умолчанию — broker.emqx.io, фиксированный порт — 1883. Если адрес ещё не задан или сохранён пустым, ESP автоматически подставляет этот брокер; сохранённый другой адрес не заменяется.

При включённом MQTT замок автоматически подключается к сохранённой домашней сети даже при выключенном отдельном флажке автоподключения Wi-Fi. Для работы нужны сохранённые SSID и пароль. Во время явного открытия Web UI используется временная сеть телефона; после завершения этого сеанса замок автоматически возвращается домой.

При появлении главного экрана приложение отправляет короткий запрос домашнего Wi-Fi через существующий защищённый служебный BLE-обмен. ESP запускает сохранённую сеть, если включено автоподключение Wi-Fi или MQTT; при выключенных настройках запрос не включает Wi-Fi. Нужны доступный Bluetooth и находящийся рядом зарегистрированный телефон. Запрос не открывает замок и не мешает активному Web UI или OTA.

После получения IP в домашней сети ESP немедленно запускает восстановление MQTT, снимая стандартную30-секундную паузу. Получение IP в локальной точке телефона это действие не запускает. Само установление соединения с брокером и подписка всё равно требуют сетевого обмена.

ESP использует постоянную MQTT3.1.1 сессию с идентификатором, производным от MAC замка. Брокер, поддерживающий persistent sessions, сохраняет подписку и QoS1 команды при временном отключении ESP, включая выход из Web UI. Отложенная команда выполняется только в исходном30-секундном окне и после прежних проверок HMAC/номера; устаревшая команда не открывает замок. Сохранение сессии брокером не гарантирует доступность общедоступного сервиса. Готовность подписки отмечается в журнале как command subscription ready.
