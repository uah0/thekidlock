# Интернет-открытие через публичный MQTT

Актуальная схема заменяет прежнее управление MQTT/ThingSpeak. Журнал ThingSpeak остаётся отдельной HTTPS-функцией.

- В Web UI задаются только включение MQTT и домен брокера. Домен без схемы и пути; используется MQTT 3.1.1/TCP без TLS, фиксированный порт 1883 в обоих клиентах. Порт не входит в API и BLE-пакет. Прежнее поле NVS зарезервировано для совместимости и не влияет на подключение.
- Client ID — lock-<MAC STA>, топики — locks/<MAC STA без двоеточий>/command и /result. Например, locks/a0f262f114b8/command. Ввести/изменить топик через API нельзя.
- Команда одна: интернет-открытие. Plaintext open/close/hold_on/hold_off, старые канальные топики, пароли MQTT и retained команды не принимаются.
- Используется LTK PEER_SEC конкретного зарегистрированного телефона. Отдельного секрета MQTT нет. ESP отправляет только собственный LTK этого телефона после encrypted+bonded BLE proof через характеристику 6f4f001d-9a7b-4c21-8d32-5e6f708192a3 существующего PhoneBeacon. Передача также доступна в служебном сеансе настроек, без включения AUTO.
- Android принимает стандартный prepared/execute GATT write, сохраняет пакет конфигурации в credential preferences, зашифрованный AES-GCM ключом Android Keystore. Этот локальный ключ защищает хранение, но не используется для MQTT/HMAC. В Web UI и логи LTK не выдаётся.
- MQTT-команда — JSON из четырёх строк: phone (тип identity-адреса 0/1 плюс MAC, 13 hex), time (Unix UTC seconds), id (положительное десятичное до 2^53−1), mac (64 lowercase hex HMAC-SHA-256). Само действие отдельно не передаётся.
- Канонический вход HMAC команды: BLELOCK1|command|<STA MAC с двоеточиями>|<phone>|<time>|<id>|open. Ключ — исходные 16 байт LTK без генерации/вывода дополнительного MQTT-ключа. Реализация: mbedTLS на ESP, javax.crypto на Android; собственные криптографические алгоритмы/шифрование не реализуются.
- Окно времени: 30 секунд назад, 5 секунд вперёд. ESP без синхронизации SNTP не исполняет команды. MAC/phone/time/id/action связаны HMAC; подпись сравнивается constant-time. Последний ID каждого телефона записывается в NVS до запроса исполнения. Он передаётся Android как нижняя граница при обновлении BLE-параметров. Повтор/retained/чужая подпись/неизвестный bond не вызывает действие.
- Ответы: JSON phone,time,id,result,faults,mac. Канонический вход: BLELOCK1|result|<target>|<phone>|<time>|<id>|<result>|<faults>. Результаты opened/closing/closed/error/interrupted; QoS1, без retain. Назначение command/result разделено в HMAC. Подтверждения сохраняются в NVS и повторяются до PUBACK. PUBACK — только приём брокером; телефон подтверждает факт по подписанному результату.
- Контроллер снимает и сохраняет hold=false, проверяет ошибки/калибровку, открывает штатным ULP. После фактического открытия ждёт FAR максимум 20 секунд, затем запрашивает CLOSE. При FAR закрытие означает штатное ожидание возврата пластины, а не мгновенный LOCKED. Интернет-цикл удерживает приоритет до факта закрытия; обычные AUTO/hold/диагностические команды не вмешиваются.
- Ошибка открытия, fault и сбой сохранения режима не выдаются за успешное открытие. Перезагрузка не повторяет принятую команду: для незавершённой записывается interrupted; обычная начальная ULP-команда закрывает замок.
- При удалении bond ESP перестаёт принимать подписи его LTK. После перепаривания приложение получает актуальный LTK. Утечка экспортированного LTK затрагивает также BLE — этот выбор сделан по прямому указанию пользователя.
- Без TLS сетевые наблюдатели и публичный брокер могут видеть метаданные/результаты, блокировать доставку или быть недоступным. HMAC обеспечивает подлинность, не конфиденциальность. Android ждёт подтверждения до 90 секунд; отсутствие финального ответа сообщает как неизвестное завершение, без автоматического нового открытия.
